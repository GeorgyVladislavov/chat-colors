# Дополнение «Чаты»: цветные статусы чатов Claude

Когда в приложении Claude открыто несколько чатов сразу, трудно понять, какой из них ещё работает, какой ждёт ответа, а какой уже закончил. Это дополнение показывает это цветом:

- 🔵 **синий** — чат работает или ждёт своего фонового помощника;
- 🟠 **оранжевый** — чат ждёт вашего ответа (задал вопрос или просит разрешения);
- 🟢 **зелёный** — чат закончил (держится, пока вы не откроете этот чат, и ещё 10 минут после этого, потом кружок пропадает; если вы написали в чат с телефона, ответ считается увиденным сразу);
- 🔴 **красный** — Claude выдал ошибку.

Где это видно:

1. **Кружок в начале названия чата** в левой панели приложения.
2. **Полоска над полем ввода** (над окошком, где вы пишете): там видны другие чаты, которые сейчас работают, ждут ответа или закончили, а вы их ещё не открыли. Кнопка **«Все чаты»** открывает и закрывает панель справа.
3. **Панель справа**: активные чаты по папкам, под каждым одна строка (что он делает, чем закончил или о чём спрашивает). Перед каждым чатом тот же цветной кружок, что и в списке слева. Название чата — ссылка: нажмите на него, и приложение откроет этот чат. Если чат ждёт ответа, там же есть кнопки, чтобы ответить ему прямо из панели. Внизу — задачи по расписанию и время их следующего запуска.

Что нужно: приложение Claude на компьютере (Windows или Mac) и раздел **Code** в нём.

**Одно правило: не переименовывайте чаты вручную** (правой кнопкой → «Переименовать»). После этого приложение считает название вашим и не даёт дополнению менять кружок в нём: в списке слева застынет старый цвет. Полоска над полем ввода и панель справа по-прежнему будут показывать верно. Если нужно другое название, попросите Claude: «переименуй чат „…“ в „…“». Если кружок уже застыл, попросите Claude в любом другом чате дать тому чату чуть другое название, и кружки вернутся.

**Если в каком-то чате нет полоски «Все чаты»**, этот чат спит. Приложение держит запущенными не больше определённого числа чатов: один на каждые 3 ГБ памяти компьютера, но не меньше шести (на 32 ГБ — 10). Когда запущено больше, открытый чат оно само не будит, а дополнение работает только в запущенном чате. Напишите в этот чат что угодно, он проснётся за несколько секунд, и полоска появится. Реже это случается, если иногда полностью перезапускать приложение. Поднять это число нельзя: приложение считает его само.

## Как установить

**С GitHub (проще всего).** Откройте приложение Claude, раздел **Code**, новый чат и напишите:

> Установи дополнение chat-colors с GitHub: репозиторий GeorgyVladislavov/chat-colors, инструкция для Claude — в его README.md (https://github.com/GeorgyVladislavov/chat-colors).

**Из архива.** Если вам прислали архив chat-colors.zip:
1. Сохраните его, например в папку «Загрузки».
2. Откройте приложение Claude, раздел **Code**, новый чат и напишите:
   > В папке «Загрузки» лежит архив chat-colors.zip. Установи это дополнение по инструкции README.md внутри архива.

Когда Claude скажет, что всё готово, полностью закройте приложение Claude и откройте снова. После этого над полем ввода появится полоска с кнопкой «Все чаты».

## Для Claude: как установить

Это мод Claude Code (плагин с хуками-функциями). Он работает в каждом чате приложения Claude и в Claude Code в терминале. Он ничего не отправляет в интернет: статусы чатов хранятся в файлах на этом компьютере. Подписи в нём на русском.

**Ставь одним способом.** Если дополнение уже стоит другим способом (есть папка `~/.claude/mods/chat-colors` или `chat-colors` в выводе `claude plugin list`), сначала убери прежний (раздел «Как удалить»): две копии будут мешать друг другу.

### Способ 1: с GitHub

1. Если в системе есть команда `claude`, выполни:
   ```
   claude plugin install chat-colors --marketplace GeorgyVladislavov/chat-colors
   ```
   Она добавит репозиторий как источник плагинов и поставит дополнение для этого пользователя. В терминальной сессии Claude Code то же самое делает строка `/plugin install chat-colors --marketplace GeorgyVladislavov/chat-colors` (на вопрос `Add marketplace?` — `y`, область — первая, Enter).
2. Если команды `claude` нет, попроси человека сделать это в приложении: в настройках плагинов (кнопка «+» у поля ввода → Plugins) добавить источник **Add marketplace** → GitHub `GeorgyVladislavov/chat-colors`, потом добавить из него плагин `chat-colors`. Названия кнопок в разных версиях приложения могут отличаться.
3. Дальше шаги 4 и 5 способа 2.

### Способ 2: из архива

1. Распакуй архив так, чтобы получилась папка `~/.claude/mods/chat-colors`, а в ней `.claude-plugin/plugin.json`, `hooks/`, `types/` и этот README. Если такая папка уже есть, это прошлая версия: замени её содержимое целиком.
   - Windows: `Expand-Archive -Path <архив> -DestinationPath $env:USERPROFILE\.claude\mods -Force`
   - macOS: `mkdir -p ~/.claude/mods && unzip -o <архив> -d ~/.claude/mods`
2. В `~/.claude/settings.json` добавь в объект `env` два значения (файла или `env` нет — создай; всё, что там уже есть, сохрани):
   - `"CLAUDE_CODE_PLUGIN_DIRS"`: полный путь к папке из шага 1 (Windows — например `C:\\Users\\<имя>\\.claude\\mods\\chat-colors`, macOS — `/Users/<имя>/.claude/mods/chat-colors`). Если такой ключ уже есть, допиши путь через `;` на Windows или `:` на macOS.
   - `"CLAUDE_CODE_PLUGIN_DIR_WATCH": "1"` — тогда правки дополнения подхватываются без перезапуска.
   После правки проверь, что файл остался правильным JSON.
3. Если в системе есть команда `claude`, проверь дополнение: `claude plugin validate <папка>` (должно быть «Validation passed») и `claude plugin test <папка>` (все тесты проходят).
4. Попроси человека полностью закрыть приложение Claude и открыть снова. На Windows оно может остаться работать у часов, справа внизу: значок Claude → правой кнопкой → «Выйти». На Mac — Cmd+Q. Уже открытые чаты подхватят дополнение только после этого, новые — сразу.
5. Скажи человеку, где смотреть: кружки в названиях чатов слева и полоска с кнопкой «Все чаты» над полем ввода.

Чат, который человек когда-то переименовал сам, кружков в названии не получит: см. раздел ниже.

## Для Claude: кружок в названии застыл (название задал человек)

Проверено на приложении Claude 4.23118 и Claude Code 2.1.321 (ноябрь 2026); в новых версиях приложение может вести себя иначе.

- **Как выглядит.** В левом списке у чата старый кружок (или никакого), а в панели справа и в полоске над полем ввода цвет верный: они берут статус из записи чата, а не из названия.
- **Почему.** Человек переименовал чат сам. Приложение помечает такое название как заданное человеком (`titleSource: "user"`) и меняет его только по одноразовому разрешению из окошка (поле `_consent`, его ставит само приложение). Дополнение вызывает `set_session_title` из хука (`$.mcp.call`), спросить человека не может и получает ошибку со словами «its title was set by the user». Кружок — часть названия: при сравнении приложение отбрасывает только невидимые знаки.
- **Что делает дополнение (с 0.5.10).** Отказ действует только на это название: при каждой смене статуса дополнение пробует снова (приложение отвечает сразу и ничего не показывает), и кружки возвращаются, как только название снова «от Claude» или «от приложения». В журнале чата (`~/.claude/chat-colors/log/<id>.log`) один раз появляется строка «кружок в названии не поменять: название … задано вручную…». До 0.5.10 отказ выключал кружки этого чата навсегда; ключ `unmarked` в хранилище больше не пишется и не читается.
- **Как вернуть кружки.** Вызови `set_session_title` для этого чата с **новым** названием, хоть чем-то отличающимся от нынешнего: на то же самое название приложение отвечает «is already named» и оставляет его за человеком. Делай это **из другого чата** (`session_id` = `local_<id>` из `list_sessions`): изнутри самого чата приложение трижды отказывало («is not the one this call was approved to replace»), окошко не появлялось, а из другого чата переименование прошло сразу. Если окошко всё-таки появится, человек нажимает «Разрешить». Проверка: повторный вызов с тем же новым названием отвечает «Renamed … (was …)», а не «is already named»; значит, название больше не человека, и кружок появится при следующей смене статуса.
- **Чему не верить.** Файл `~/.claude/sessions/<pid>.json` (поле `nameSource`) показывает взгляд процесса чата, а не приложения: после такого переименования там может по-прежнему стоять `user`.
- **Если человек не хочет менять название.** Пусть уберёт кружок из названия сам: неверного цвета тогда не будет, а статус виден справа и в полоске.

## Для Claude: в чате нет полоски (чат спит)

Проверено на приложении Claude 5.1231.2 для Windows и Claude Code 2.1.321 (ноябрь 2026); в новых версиях может быть иначе.

- **Как выглядит.** В одном чате нет полоски «Все чаты» над полем ввода и панели, а в соседних есть. Статус этого чата в панели других чатов при этом виден.
- **Почему.** Дополнение работает внутри процесса Claude этого чата. Приложение держит ограниченное число таких процессов: `max(6, floor(память / 3 ГБ))`, на 32 ГБ — 10 (в коде приложения рядом с `[CliGovernor]`, настройки для этого нет). Открытый спящий чат приложение будит заранее, только пока лимит не набран. Иначе в журнале приложения (Windows: `%LOCALAPPDATA%\Claude\Logs\main.log`) при каждом открытии стоит `[CliGovernor] at cap; yielding warm spawn`, и процесс не запускается. Простаивающие чаты приложение само не усыпляет (в журнале `would evict`), поэтому за день живых набирается больше лимита: сообщение человека лимит не держит (`soft_cap_exceeded`).
- **Какие чаты живы.** Файлы `~/.claude/sessions/<pid>.json`, у которых процесс с этим pid жив; в файле название чата и папка.
- **Что делать.** Попросить человека написать в этот чат: на сообщение приложение будит чат всегда. Чтобы реже, — полностью перезапускать приложение: после перезапуска живых ноль. Поднять лимит нельзя; код приложения не править.

## Для Claude: как устроено и как менять

- Карта файлов в `hooks/`: `register.tsx` — запись чата о себе, обход всех чатов, события; `view.tsx` — полоска, панель, кнопки и ссылки; `host.ts` — вызовы приложения, id чата, журнал; `appfiles.ts` — файлы приложения о чатах; `rows.ts` — сборка списка и цвета; `record.ts` — действия словами, шаг плана, итог, правило конца ответа; `testkit.ts` — общая обвязка тестов. `types/index.d.ts` — типы. Тесты: `*.test.ts(x)`, запуск — `claude plugin test <папка>`.
- Два правила движка для файлов, кроме `register.tsx`: функцию, которой передают `$` через импорт, объявляют как `function`, а не стрелкой; значение состояния (`atom`) читают и пишут в том файле, где оно объявлено. Иначе дополнение не загрузится, и `claude plugin test` это покажет.
- Каждый чат пишет свою запись в `~/.claude/chat-colors/<id>.json` и короткий журнал событий в `~/.claude/chat-colors/log/<id>.log`. Если чат показан не тем цветом, сначала смотри журнал.
- Правило цвета нарочно простое, не усложняй его: `turn.start` → синий; окошко `AskUserQuestion`/`ExitPlanMode` или запрос разрешения → оранжевый, а когда этот самый вызов закончился → снова синий (только он: вызов итогового блока `wrap_up` заканчивается уже после хода, и его вопрос должен остаться); `turn.complete` → красный при ошибке Claude, оранжевый при вопросе в итоговом блоке или прежнем вопросе без ответа, синий, если в фоне осталась работа, иначе зелёный. Не выставляй статус по `classic.Stop` (он только сообщает список фоновой работы), не добавляй самопроверку конца хода и угадывание «завис/оборвался»: всё это пробовали, и это ломало оранжевый.
- Зелёный держится, пока человек не откроет чат. Приложение подключает своё окно к чату на экране (`session.attach`) и отключает, когда человек уходит; пока окно подключено, `$.session.surfaces()` не пуст. Чат, закончивший без окна, пишет в запись `unseen: true`; когда окно подключается — `seenAt`, и через 10 минут (`SEEN_MS` в `rows.ts`) кружок снимается, а чат уходит из полоски и панели. Чат, закончивший у человека на глазах, считается увиденным сразу. Запуски задач по расписанию и записи старых версий — час от конца (`RECENT_MS`). После перезапуска чат продолжает отсчёт по записи. Проверяет `hooks/seen.test.ts`.
- Ещё два признака «увидел» (v0.4.0, `hooks/focus.test.ts`). Первый: ход, в который человек написал с телефона через Remote Control (`prompt.submit` с `origin.kind === 'bridge'`), в конце сразу считается увиденным. Второй: приложение держит ограниченное число работающих чатов (раздел «Для Claude: в чате нет полоски» выше), остальные спят. Спящий чат приложение показывает из файла, не запуская его, и дополнение внутри этого чата ничего не слышит. Зато приложение записывает время, когда его окно последний раз показывало чат: поле `lastFocusedAt` в своём файле на чат (`%LOCALAPPDATA%/Claude-Data/*/claude-code-sessions/<…>/<…>/local_<id>.json`, или `%APPDATA%/Claude/…`, или `~/Library/Application Support/Claude/…`). Если чат показали после конца ответа, это и есть `seenAt`. Кружок со спящего чата, у которого вышли его 10 минут, снимает любой работающий чат (`staleMarks` в `rows.ts`). Формат этого файла — внутренний формат приложения. Если файлы не найдены или поле пропало, всё работает как раньше.
- Ход закончился, а работа, оставленная в фоне, ещё идёт (помощник, команда, рабочий процесс): чат не готов и остаётся синим (v0.5.4, `hooks/background.test.ts`). `classic.Stop` приходит сразу перед `turn.complete` и перечисляет фоновые задачи в `background_tasks` (проверено 06.11.2026 на настоящем запуске); дополнение только читает список. Ждать можно не всё из него, только типы `subagent`, `workflow`, `shell` (`WAITED_FOR` в `record.ts`, v0.5.5): они заканчиваются и будят чат. В том же списке лежит бессрочная слежка `monitor`: приложение само включает её при каждой публикации страницы-артефакта, и чат, ждавший её, остался бы синим навсегда. Есть там и служебные задачи движка (`dream`, `memory import` и другие), которые никого не будят. Новый тип добавляй в список, только проверив, что он будит чат. В журнале чата видно, что осталось в фоне: «конец хода: answer, в фоне: subagent, monitor». Когда очередная работа заканчивается, движок будит чат (`task-notification`), и начинается новый ход; зелёный придёт в конце хода, после которого список пуст. Вопрос в итоговом блоке, ошибка и остановка важнее фоновой работы. Пока чат ждёт, приложение пишет `isRunning: false`, поэтому он раз в минуту обновляет `activityAt`, иначе другие чаты сочтут его закончившим (`ENDED_MS`). Перезапуск обрывает фоновую работу: чат считается закончившим (`resume`). Обновление дополнения её не трогает, и чат остаётся синим (v0.5.7): обновление отличают по списку `rows`, который переживает его, но не перезапуск. Предел: команда, которая сама не кончается (например, сервер в фоне), держит чат синим, пока в него не напишут; в панели видно, чего он ждёт.
- Вопрос человеку остаётся открытым, пока человек не ответит (v0.5.6, `hooks/question.test.ts`). Чат будят не только люди: пишут другие чаты, заканчивается фоновая работа, приложение присылает заметки о дочерних чатах. Такой ход синий, а в конце чат снова оранжевый с прежним вопросом и кнопками (поле `unanswered`). Ответить может только человек: `isOtherSender` в `record.ts` смотрит `origin.kind` из `prompt.submit`, и ответом считаются только `composer` и `bridge` (v0.5.7). `sdk` — это заметки приложения и задания от других чатов, ответа человека среди них в журналах не нашлось. Ответ кнопкой из панели приходит как сообщение другого чата (`peer`), его отличают только слова `PANE_REPLY`: не меняй их в `sendAnswer` отдельно. Вопрос закрывают: сообщение человека (даже посреди такого хода), новый вопрос чата, итоговый блок без вопроса (чат сам говорит, что ждать нечего), ошибка и остановка.
- Что закреплено проверкой 0.5.9 (`hooks/review*.test.*`):
  - Инструменты, план и итоговый блок помощника (`e.agentId` в `tool.call`) — не чата: запись они не меняют. Запрос разрешения от помощника — исключение: отвечает человек, поэтому чат оранжевый.
  - Окошко живёт ровно столько, сколько вызов, который его показал (`toolRuns`, `askerOf` в `record.ts`). Конец другого инструмента оранжевый не снимает; из двух окошек закрытие первого оставляет второе. `AskUserQuestion` приходит и как запрос разрешения, но его вопрос остаётся своим.
  - Разрешение и план на одобрение кончаются вместе с окошком (`isDialogAsk`): они не становятся «вопросом без ответа». Вопрос словами остаётся.
  - Перезапуск обрывает ход: запись «работает» или окошко разрешения становится «закончил», если не идёт ход и не работает помощник (`resume`). Это факт, а не угадывание: в новом процессе хода нет.
  - Чат с открытым инструментом или фоновой работой раз в минуту подаёт признак жизни. Без него дольше часа (`RECENT_MS`) чат с открытым инструментом считается умершим, а не ждущим ответа. Без открытого инструмента признака нет: чат, чей конец хода не услышан, должен затихнуть, чтобы другие увидели конец.
  - Отказ в переименовании — только ошибка приложения со словами про название от человека. Успех повторяет название, какие бы слова в нём ни были; другая ошибка проходит. С 0.5.10 отказ не навсегда (раздел «кружок в названии застыл» выше, `hooks/review-marks.test.ts`).
  - Запись, отстающая от `lastActivityAt`, защищает кружок только 10 минут: приложение двигает это время без всякого хода. Кружок снимают и с синего чата, умершего посреди хода; на первом обходе после сна не снимают.
  - Кнопка ответа у запланированной задачи шлёт в чат её последнего запуска (`chatId`). Тот же вопрос, заданный позже, снова получает кнопки (`askedAt`).
  - Пустые `title`, `lastActivityAt`, `cwd` и список не того вида не ломают панель (`saneChats` в `rows.ts`).
- Чаты в панели не меняют свои места: место даётся чату один раз, новый чат встаёт сверху своей папки.
- В панели перед чатом и в легенде стоят те же кружки 🔵🟠🟢🔴, что и в названиях чатов (`MARK` в `rows.ts`; ⚪ — нет данных): они раза в три крупнее точки «●», и их лучше видно (v0.5.2, просьба 05.11.2026). В полоске над полем ввода точки «●» прежние.
- Название чужого чата в панели — ссылка (v0.5.0, `hooks/link.test.tsx`), только в приложении на компьютере. Это `Markdown` с `onLinkPress`: нажатие приходит в дополнение, а его адрес `https://claude.ai/code/<id>` не открывается. Дополнение передаёт системе ссылку самого приложения `claude://code/continue?session=local_<id>` (ею меню значка на панели задач открывает чаты): на Windows — `rundll32.exe url.dll,FileProtocolHandler <ссылка>`, а если он не запустился, `cmd /c start "" <ссылка>`; иначе `open`, потом `xdg-open`. Не `explorer.exe`: он ссылку `claude://` молча проглатывает (проверено 05.11.2026 по журналу приложения, v0.5.1). В журнале чата строка «передал ссылку на чат … (программа, код)»; дошла ли ссылка до приложения, видно в его `main.log` по строке `second-instance`. Открыть чужой чат через `ccd_window` нельзя: он открывает только чаты, запущенные из этого. Ссылку приложение рисует своим синим, задать ей цвет статуса нельзя. Пробовали и кнопку: в ней приложение не показывает цвет текста (0.6.x, копии в «chat-colors — копии»). Свой чат и задачи по расписанию — без ссылки. На телефоне ссылки нет: нажатие повернуло бы окно на компьютере, а не на телефоне.
- Правь копию дополнения, прогоняй тесты и переноси её целиком: открытые чаты подхватывают каждое сохранение сразу. Чат, в котором правят дополнение, подхватывает новую версию в момент окончания своего ответа и может не услышать этот конец, поэтому живой цвет проверяй в ответе, в котором дополнение не менялось.

## Как обновить

- Поставлено с GitHub: `claude plugin marketplace update chat-colors`, затем `claude plugin update chat-colors@chat-colors`, затем полностью перезапустить приложение.
- Поставлено из архива: шаг 1 способа 2 с новым архивом (папка заменяется целиком). Открытые чаты подхватят новую версию сами.

## Как удалить

- Поставлено с GitHub: `claude plugin uninstall chat-colors@chat-colors` (или удалить плагин в настройках плагинов приложения).
- Поставлено из архива: убери из `env` в `~/.claude/settings.json` два значения из шага 2 способа 2 и удали папку `~/.claude/mods/chat-colors`.

Потом удали папку `~/.claude/chat-colors` (там записи о статусах чатов) и перезапусти приложение.
